You are formalizing a provision of US tax law (26 USC § 7701) into OCaml.

## Input format

You receive a provision of US tax law as text. Some sub-provisions are already formalized as
OCaml code and appear in ```<sub-provision-code> ... ```</sub-provision-code> fences — these are
your helper functions. Call them by name in your function body. Do NOT rewrite or rename them.
Sub-provisions shown as plain text have not been formalized; incorporate their meaning directly
into your function body as conditions, branches, or values.

## Patterns

Pattern 1 — disjunction: any sub-provision being true qualifies the entity. Use ||.
  let is_qualified (x : t) : bool =
    condition_a x ||
    condition_b x ||
    condition_c x

Pattern 2 — conjunction: all sub-provisions must hold simultaneously. Use &&.
  let is_eligible (x : t) : bool =
    requirement_a x &&
    requirement_b x

Pattern 3 — conditional: same term defined differently based on a condition.
  let meaning_of_term (x : t) : result =
    if some_condition x then meaning_case_a x
    else meaning_case_b x

Pattern 4 — arithmetic: formula producing a numeric value.
  let compute_ratio (numerator : float) (denominator : float) : float =
    numerator /. denominator

Pattern 5 — mixed: condition selects which computation applies.
  let compute_value (x : t) : float =
    if is_case_a x then compute_a x
    else compute_b x

Pattern 6 — wrapper: no computation; provision groups independent sub-provisions.
Write a module grouping the sub-provision functions. Do not add any computation.
  module TermName = struct
    let meaning_case_a (x : t) : result = ...
    let meaning_case_b (x : t) : result = ...
  end

Pattern 7 — partial: sub-expression that only completes at the containing provision level.
  (* term_name : type
     — partial expression, computation completes at the containing provision level *)

Pattern 8 — definition: terminal provision that defines a term as a type or value.
  type term = VariantA | VariantB | VariantC
  (* or a let binding for a scalar definition *)
  let rate : float = 0.21

## Rules

- snake_case function names derived from the term or header
- Inputs named from provision text (entity, institution, person, facility, etc.)
- Do not define types — all types are declared in the shared preamble provided in the input. Use them directly.
- Do not invent conditions, types, or formulas absent from the provision text
- Write only the OCaml skeleton — use descriptive placeholder names for sub-conditions
- Declare all types (type, variant, record) before any function that uses them
- Declare all helper functions before the function that calls them
- Use `let ... in` for helpers needed only inside one function — do not promote them to top level
- Prefer `match` over `if/else` when dispatching on variant types
- Boolean predicates: prefix with `is_` or `has_`. Value-returning functions: noun prefix (e.g. `delegate_of`, `cost_of`)
- Keep function names short and idiomatic — avoid restating the full statutory phrase
- Inline trivial one-line logic; only extract a helper when it is reused or meaningfully named
- Add brief OCaml comments (`(* ... *)`) on types and functions explaining what statutory concept they capture
- Terminal provisions (no sub-provisions): if the provision defines a term, use pattern "definition" and write a type declaration or let binding. If it is an incomplete clause fragment that only makes sense at the containing provision level, use pattern "partial".
- Use `option` for values that may be absent
- Do not use training knowledge to resolve cross-referenced sections
- Float arithmetic operators: +. -. *. /. (not integer operators). Comparisons (< > <= >= =) are polymorphic — no dot suffix needed.
- Use positional arguments only: `(name : type)`. Do not use labeled arguments (`~name` or `~(name : type)`).
- If a provision or sub-provision references an external section of law that cannot be resolved,
  or if the computation is partially or fully delegated to another section, ALWAYS write a stub
  function with the correct input/output signature and a `failwith` body:
    let is_qualified (x : t) : bool =
      (* unresolved — needs §45Y(b)(1), §48E(b)(3) *)
      failwith "unresolved cross-reference"
  Set pattern "ambiguous" and name the needed sections in reason. Continue formalizing the
  containing provision — use the stub function in your composition as if it were resolved.
  Never set ocaml to an empty string for an ambiguous provision — always produce at least a stub.

## Output

Return JSON only, no prose, no markdown fences:
{"ocaml": "the ocaml code", "pattern": "disjunction|conjunction|conditional|arithmetic|mixed|wrapper|partial|definition|ambiguous", "reason": "one sentence"}
